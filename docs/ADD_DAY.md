# Как добавить или изменить день

## Новый день

```bash
uv run tools/new_day.py day-45 --label 45 --copy-from day-44
# отредактируйте content/days/day-45.json
uv run tools/validate.py
git add content/days && git commit -m "content: add day 45" && git push origin main
```

`new_day.py` локально пересобирает `content/days.json` (навигация, порядок и строка поиска). Этот файл генерируется и исключён из Git. При публикации GitHub Actions создаёт его заново из JSON-файлов дней.
Service worker получает список дней из сгенерированного `days.json` и кэширует все перечисленные файлы.

## Правка существующего дня

1. Откройте `content/days/day-N.json` и измените названия или граммовки.
2. Запустите `uv run tools/build_index.py` — локально обновится строка поиска. Индекс не нужно коммитить: CI пересоберёт его перед публикацией.
3. Коммит и push.

Офлайн-копия на телефоне обновится при следующем открытии с интернетом
(service worker сначала спрашивает сеть и только потом берёт кэш).

## Вариант дня (как `33 (2)`)

```bash
uv run tools/new_day.py day-33-var-3 --label "33 (3)" --copy-from day-33
```

Вариант встаёт сразу после основного дня и не увеличивает счётчик «N дней».
`day-33-var-3` должен иметь `"variantOf": "day-33"`; ссылка всегда ведёт на существующий основной день, а не на другой вариант.

## Версия формата данных

В `content/meta.json` хранится поле `dataVersion`. Текущая версия формата — `1`.
При несовместимом изменении структуры JSON увеличивайте эту версию и описывайте миграцию. Не меняйте её при обычном добавлении дней, блюд или ингредиентов.

## Формат файла дня

```json
{
  "id": "day-1",
  "label": "1",
  "variantOf": null,
  "meals": [
    {
      "type": "lunch",
      "dish": "фунчоза вок",
      "ingredients": [{ "name": "Фунчоза (в сухом виде)", "grams": 39 }]
    }
  ]
}
```

- `type`: `breakfast`, `lunch`, `dinner`, `snack` (любой может отсутствовать, тип не повторяется).
- `dish`: название блюда или `null`.
- `grams`: целое число больше нуля; на экране выводится как «39 г» (с учётом выбранных порций).
- Каждый элемент `meals` и `ingredients` должен быть JSON-объектом. `ingredients` — непустой список.
- Названия ингредиентов должны быть непустыми строками; HTML-теги в названиях не допускаются.
- Больше 5 строк в приёме пищи: лишние автоматически прячутся за кнопкой «Показать ещё N».
