# Template Menu — персональное меню питания (PWA)

Шаблон для быстрого создания отдельного репозитория под каждого клиента.
Каждый клиент получает независимый GitHub Pages, а общая Git-история позволяет
переносить обновления приложения из шаблона через upstream. Приложение работает
офлайн, поддерживает меню на N дней, поиск, тёмную тему и установку на домашний экран.

## Быстрый старт для нового клиента

1. На GitHub создайте **пустой** репозиторий клиента, например `menu-client-a` (без README и `.gitignore`).
2. Клонируйте шаблон и подключите репозиторий клиента как `origin`:

   ```bash
   git clone https://github.com/Wwwoper/template-menu.git menu-client-a
   cd menu-client-a
   git remote rename origin upstream
   git remote add origin https://github.com/Wwwoper/menu-client-a.git
   git push -u origin main
   ```

   Замените URL и имя репозитория на свои. `upstream` будет источником обновлений шаблона, `origin` — репозиторием клиента.

3. Установите зависимости инструментов (нужен [uv](https://github.com/astral-sh/uv) и Python ≥ 3.11):

   ```bash
   uv sync
   ```

4. Инициализируйте под клиента:

   ```bash
   uv run tools/init_client.py --name "Меню Анны Ивановой"
   ```

5. Добавьте дни меню (см. ниже) и опубликуйте.

После инициализации появится `CLIENT_TEMPLATE_VERSION` — зафиксированная версия
шаблона, из которой создан клиент. Добавьте этот файл в Git вместе с остальными
изменениями клиента. Не обновляйте его при обычном получении изменений из
`upstream`: он хранит именно исходную версию и помогает определить baseline
истории шаблона.

### Что делает `init_client.py`

Скрипт заменяет нейтральное название «Меню клиента» в:

- `content/meta.json` — заголовок на сайте;
- `manifest.json` — название PWA на телефоне;
- `index.html` — `<title>`, `<h1>` в шапке, sidebar, subtitle, apple-mobile-web-app-title.

Поле `short_name` в `manifest.json` по умолчанию остаётся «Меню» (короткое имя под иконкой).
При необходимости передайте `--short-name "Анна"`.

Версия в корневом файле `TEMPLATE_VERSION` — версия текущего релиза шаблона.
`init_client.py` считывает её и один раз создаёт в клиентском репозитории
`CLIENT_TEMPLATE_VERSION`. Если файл уже существует, скрипт его не перезаписывает.
Версия проекта из `pyproject.toml` и версия формата данных не заменяют эту отметку.
Перед выпуском релиза обновляйте `TEMPLATE_VERSION` и создавайте Git-тег с тем же
значением. До первого релиза используется `0.0.0-dev`.

После запуска проверьте, что старого названия не осталось:

```bash
grep -rn "Меню клиента" . --exclude=README.md
```

Команда не должна ничего вывести.

### Создание клиента из Excel одной командой

Для автоматической инициализации и импорта меню положите исходную книгу `.xlsx`
в локальную папку `input/` и запустите:

```bash
uv run tools/create_client.py
```

Сценарий найдёт XLSX (если файлов несколько — предложит выбрать), запросит имя
клиента так, как оно записано в первой строке листов, извлечёт дни, проверит их
структуру и связи вариантов, покажет сводку и попросит подтверждение. После
подтверждения он:

1. запустит `init_client.py` и запишет `CLIENT_TEMPLATE_VERSION`;
2. создаст JSON-файлы в `content/days/` без перезаписи существующих файлов;
3. построит `content/days.json` тем же кодом, который используется при проверке
   и публикации;
4. переместит исходный XLSX в `input/archive/`.

`input/` целиком исключён из Git: исходные таблицы и архив не попадут в коммиты,
GitHub Actions или GitHub Pages. Не помещайте в эту папку файлы, которые должны
публиковаться. Архивирование выполняется только после успешного импорта.

При необходимости можно передать параметры без интерактивного ввода:

```bash
uv run tools/create_client.py --input input/menu.xlsx --client "Анна Иванова" --short-name "Анна"
```

Для автоматического подтверждения добавьте `--yes`. Повторный запуск в уже
инициализированном репозитории или при наличии JSON-дней будет остановлен,
чтобы не смешать данные разных клиентов. Импортёр отдельно можно запускать
через `uv run tools/import_xlsx.py --input input/menu.xlsx --client "Анна Иванова"`.

## Добавление дней меню

Количество дней на странице определяется автоматически из `content/days.json`.
Не нужно вручную менять «N дней» в `index.html`.

### Создание нового дня

Рекомендуемый способ — скопировать структуру с уже существующего дня:

```bash
uv run tools/new_day.py day-13 --label 13 --copy-from day-12
```

Скрипт создаст `content/days/day-13.json` с теми же приёмами пищи и ингредиентами, что и у `day-12`, и сразу пересоберёт индекс.

Если дня для копирования ещё нет, можно создать «пустой» шаблон:

```bash
uv run tools/new_day.py day-1 --label 1
```

В этом случае файл будет содержать четыре заготовки (завтрак, обед, ужин, перекус) с одним ингредиентом-заглушкой. Их нужно заменить на реальные данные.

После редактирования файлов дней проверьте данные и локально пересоберите индекс для просмотра приложения. Валидатор проверяет структуру каждого дня, граммовки и связи вариантов с основными днями:

```bash
uv run tools/validate.py
uv run tools/build_index.py
```

`content/days.json` — генерируемый файл: он добавлен в `.gitignore` и не коммитится. При публикации GitHub Actions заново создаёт индекс из `content/days/*.json` и включает его в артефакт сайта. В Git хранятся только исходные JSON-файлы дней.

Заголовки «Меню на N дней» и склонение («1 день», «2 дня», «5 дней») обновятся автоматически.

### Можно ли убрать перекус / любой приём пищи?

Да. Если в конкретном дне нет перекуса (или завтрака, обеда, ужина) — просто удалите соответствующий объект из массива `meals`.  
Любой из типов (`breakfast`, `lunch`, `dinner`, `snack`) может отсутствовать. Главное — не оставлять `meals` пустым и не дублировать один и тот же `type`.

### Варианты дня

Варианты (например `33 (2)`) добавляются так:

```bash
uv run tools/new_day.py day-33-var-2 --label "33 (2)" --copy-from day-33
```

Они отображаются в навигации, но не увеличивают счётчик основных дней.

Подробнее о формате файла дня: [docs/ADD_DAY.md](docs/ADD_DAY.md).

## Публикация изменений

Если меняли оболочку приложения, список ресурсов или стратегию кэширования, увеличьте `VERSION` в `service-worker.js`. Это заставит браузер создать новый офлайн-кэш.

Сохраните изменения клиента (JSON-дни и настройки) обычным коммитом:

```bash
git add content/days content/meta.json
git commit -m "content: update client menu"
git push
```

`content/days.json` добавлять в Git не нужно: файл генерируется во время сборки.

### Деплой через GitHub Actions

В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**. После push в `main` (или `master`) workflow автоматически:

1. проверит JSON-файлы дней;
2. соберёт `content/days.json`;
3. запустит Python- и JavaScript-тесты;
4. подготовит статический сайт и опубликует его в GitHub Pages.

Для pull request выполняются проверки и сборка индекса, но публикации нет.

Service Worker кэширует сгенерированный индекс и все файлы дней, перечисленные в нём. Если хотя бы один обязательный файл отсутствует, установка новой версии Service Worker не завершится успешно — это предотвращает публикацию неполного офлайн-приложения.

Service Worker и манифест рассчитаны на раздачу из корня сайта.

### Переход существующего клиента на генерируемый индекс

Если клиентский репозиторий ранее был создан через **Use this template**, файл `content/days.json` может уже отслеживаться Git. Перед первым обновлением из шаблона перестаньте отслеживать его:

```bash
git switch main
git pull origin main
git rm --cached content/days.json
printf '\n# Generated at build time\ncontent/days.json\n' >> .gitignore
git add .gitignore
git commit -m "chore: stop tracking generated days index"
rm content/days.json
```

После этого добавьте `upstream`, получите обновления шаблона и выполните merge. Перед локальным просмотром или публикацией индекс будет создан командой `uv run tools/build_index.py` или GitHub Actions. Исходные `content/days/*.json` эта миграция не затрагивает.

## Требования

- Python ≥ 3.11
- [uv](https://github.com/astral-sh/uv) (для запуска tools/ и тестов)
- Современный браузер с поддержкой ES modules и Service Worker

## Структура

```
input/                # локальные XLSX и архив; содержимое не отслеживается Git
content/
  meta.json          # заголовки, типы приёмов пищи, версия формата данных (dataVersion)
  days.json          # генерируется в CI и не хранится в Git
  days/              # исходные клиентские JSON: day-1.json, day-2.json, …
tools/               # create_client, import_xlsx, init_client, new_day, validate, build_index
shared/              # css + js приложения
icons/               # PWA-иконки
docs/ADD_DAY.md      # формат дня и инструкции
```
